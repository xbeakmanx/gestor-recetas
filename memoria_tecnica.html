1. Introducción y objetivos

El Gestor de Recetas es una plataforma web desarrollada con Django que permite a los usuarios crear, organizar, buscar y compartir recetas de cocina. El proyecto responde a la necesidad de tener un sistema centralizado donde gestionar recetas con sus ingredientes, categorías, comentarios y puntuaciones.

Objetivos del proyecto

  • Desarrollar una aplicación web CRUD completa con Django y Python.
  • Implementar un modelo de datos relacional con 8 entidades interconectadas.
  • Aplicar el patrón de capa de servicios para separar la lógica de negocio.
  • Integrar django-pandas para la exportación de datos a CSV y XLSX.
  • Crear una interfaz de usuario funcional y responsive con Bootstrap 5.
  • Implementar sistema de autenticación basado en sesiones.
  • Incorporar sistema de favoritos y comentarios con puntuación.

2. Arquitectura del sistema

La aplicación sigue la arquitectura MVT (Model-View-Template) propia de Django, complementada con una capa de servicios que encapsula la lógica de negocio.

6. Funcionalidades principales

6.1 CRUD de Recetas

Operaciones completas de creación, lectura, actualización y eliminación de recetas. Cada receta incluye título, descripción, instrucciones, categoría, tiempo de preparación, dificultad e ingredientes asociados mediante un FormSet dinámico.

6.2 CRUD de Categorías e Ingredientes

Gestión independiente de categorías e ingredientes. Las categorías se pueden crear directamente desde el formulario de recetas mediante un botón "+" que redirige al formulario de creación y vuelve al formulario de receta.

6.3 Sistema de autenticación

Autenticación basada en sesiones de Django con registro e inicio de sesión. Las contraseñas se almacenan como hash SHA-256. La sesión guarda el usuario_id y usuario_nombre para identificar al usuario en toda la aplicación.

6.4 Favoritos

Los usuarios autenticados pueden marcar recetas como favoritas. El botón de corazón aparece en las listas y en el detalle de cada receta. Los usuarios no autenticados ven el corazón como enlace al login. La sección "Favoritas" muestra todas las recetas guardadas.

6.5 Comentarios y puntuación

Sistema de comentarios con puntuación de 1 a 5 estrellas en cada receta. Los comentarios se muestran ordenados por fecha descendente. Se utiliza un filtro de template personalizado (estrellas) para convertir la puntuación numérica en representación visual con caracteres ★ y ☆.

6.6 Filtrado y búsqueda

Barra de filtros en la lista de recetas que permite filtrar por categoría, dificultad y término de búsqueda. Los filtros se preservan durante la paginación mediante parámetros GET en las URLs.

6.7 Logging

Sistema de logging configurado con dos handlers: archivo (proyecto.log) y consola. Se registran las acciones principales: creación, actualización y eliminación de recetas, comentarios, exportaciones, login/registro y errores.

7. Capa de servicios

La lógica de negocio se encapsula en dos servicios principales dentro de services.py, separando las responsabilidades de las vistas.

RecetaService

Métodos estáticos para gestionar recetas:

  • listar(filtros) — Consulta con filtros dinámicos (categoría, dificultad, búsqueda) usando Q objects y select_related.
  • obtener(pk) — Obtención de receta con prefetch_related para ingredientes, imágenes y comentarios.
  • crear(datos, ingredientes_data) — Creación de receta con sus ingredientes asociados.
  • actualizar(receta, datos) — Actualización mediante setattr dinámico.
  • eliminar(receta) — Eliminación con registro de log.
  • estadisticas() — Estadísticas generales usando Avg, Count y annotate.

ExportService

Exportación de todas las tablas de la base de datos:

  • exportar_csv(destino) — Genera 8 archivos CSV (uno por modelo) usando DataFrameManager.
  • exportar_xlsx(destino) — Genera un archivo Excel con 8 hojas (una por modelo) usando openpyxl.
  • exportar_todo(destino) — Ejecuta ambas exportaciones.

8. Exportación de datos con django-pandas

Todos los modelos incluyen un DataFrameManager (alias df) proporcionado por django-pandas. Esto permite convertir cualquier QuerySet a un DataFrame de pandas con una sola llamada: 

df = modelo.df.all().to_dataframe()

Los datos se exportan a:

  • CSV: 8 archivos individuales con codificación utf-8-sig (compatible con Excel en español).
  • XLSX: 1 archivo con 8 hojas, generado con pd.ExcelWriter y motor openpyxl.

La interfaz de exportación permite al usuario seleccionar el formato deseado (CSV, XLSX o ambos) mediante un formulario.

10. Manual de usuario

Instalación y puesta en marcha

  1. Clonar el repositorio.
  2. Crear un entorno virtual: python -m venv venv
  3. Activar el entorno: venv\Scripts\activate (Windows)
  4. Instalar dependencias: pip install -r requirements.txt
  5. Ejecutar migraciones: python manage.py migrate
  6. Cargar datos de ejemplo: python manage.py cargar_datos
  7. Iniciar el servidor: python manage.py runserver
  8. Abrir en el navegador: http://127.0.0.1:8000/

Uso de la aplicación

  • Página de inicio: Muestra estadísticas generales y las últimas recetas publicadas.
  • Recetas: Lista con filtros por categoría, dificultad y búsqueda. Se pueden crear, editar y eliminar recetas. Al crear una receta se añaden ingredientes dinámicamente con el botón "Añadir ingrediente".
  • Categorías / Ingredientes: CRUD completo accesible desde la barra de navegación.
  • Favoritos: Hacer clic en el corazón para guardar/quitar una receta de favoritos. Accesible desde el menú "Favoritas" (requiere iniciar sesión).
  • Comentarios: En la página de detalle de cada receta se puede añadir un comentario con puntuación del 1 al 5.
  • Exportar: Acceder a la sección "Exportar" para descargar los datos en CSV, XLSX o ambos formatos.
  • Registro / Login: Crear una cuenta o iniciar sesión para acceder a funcionalidades como favoritos y comentarios.

11. Justificación técnica

Decisiones de diseño

  • Class-Based Views: Se eligieron las CBV de Django por la reutilización de código que ofrecen (herencia, mixins) y porque se ajustan mejor a operaciones CRUD estándar que las vistas basadas en funciones.
  • Capa de servicios: Se separó la lógica de negocio en RecetaService y ExportService para mantener las vistas limpias y facilitar pruebas unitarias futuras.
  • Autenticación por sesiones: Se implementó un sistema de autenticación personalizado basado en sesiones de Django en lugar de usar django.contrib.auth, para demostrar el manejo manual de sesiones y hashing.
  • InlineFormSet: Para la relación N:M entre recetas e ingredientes se usa inlineformset_factory con formularios dinámicos en JavaScript, permitiendo añadir y quitar ingredientes sin recargar la página.
  • DataFrameManager: Cada modelo incluye un DataFrameManager de django-pandas para convertir QuerySets a DataFrames de forma directa, facilitando la exportación masiva de datos.
  • SQLite3: Se eligió por ser la base de datos por defecto de Django, sin necesidad de configuración adicional, adecuada para el alcance del proyecto.
  • Imágenes por URL: El modelo ImagenReceta almacena URLs externas en lugar de archivos locales, evitando la necesidad de almacenamiento de medios en el servidor, lo cual es compatible con despliegues en plataformas serverless.

Patrones aplicados

  • MVT (Model-View-Template): Patrón arquitectónico de Django para la separación de responsabilidades.
  • Service Layer: Capa intermedia entre vistas y modelos que encapsula la lógica de negocio.
  • Mixin (UsuarioMixin): Reutilización de la lógica de obtención del usuario activo en múltiples vistas.
  • Template Inheritance: Template base (base.html) del que heredan todas las páginas.
  • Custom Template Tags: Filtros reutilizables para formatear datos en las plantillas.

Configuración relevante

  • LANGUAGE_CODE = 'es' — Interfaz de administración y mensajes en español.
  • TIME_ZONE = 'Europe/Madrid' — Zona horaria española.
  • USE_TZ = False — Fechas sin conversión de zona horaria para simplificar el manejo.
  • ALLOWED_HOSTS = ['*'] — Permite despliegue en cualquier dominio.
  • Logging: Logger "proyecto" con formato detallado, nivel DEBUG en consola e INFO en archivo.
